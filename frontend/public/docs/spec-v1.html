1.서비스 개요

IceCraft는 실시간 화상채팅 위에서 진행하는 마피아 게임 웹 서비스입니다. 참가자 전원이 캠과 마이크를 켠 상태로 낮 토론과 밤 행동을 반복하며, 게임 서버가 사회자 역할을 맡아 단계 전환 · 미디어 on/off · 투표 집계를 자동 진행합니다.

  • 2024년 4인 팀 프로젝트로 개발되었습니다.
  • 화상 스트리밍은 LiveKit(SFU)을 사용하고, 게임 진행은 Socket.IO 서버가 담당합니다.
  • 게임 종류로 "마피아"와 "노래맞추기" 두 가지를 기획했으나, 노래맞추기는 UI 자리만 존재하는 미구현 상태입니다.

3.화면 구성 및 사용자 흐름

인트로 /
  ├─ 로그인 /login ── 소셜 로그인 → OAuth 콜백 /sns-login
  ├─ 회원가입 /register
  ▼
로비 /main ──[방 만들기 · 입장 · 빠른입장]──▶ 게임 방 /room/{id}
  ├─ 랭킹 /ranking
  ├─ 게임 방법 /mafiainfo
  └─ 문의 /inquiry
  • 로그인 상태로 인트로 · 로그인 · 회원가입 페이지에 접근하면 로비로 리다이렉트합니다.
  • 게임 방은 로비를 거치지 않은 직접 URL 진입을 차단합니다 (입장 상태가 아니면 로비로 강제 이동).

4.기능 명세

4.1 인증

FR-101 이메일 회원가입

  • 이메일 형식 검사와 [중복확인] 버튼으로 account_table 중복 여부를 확인합니다.
  • 닉네임은 2~6자(영문 · 한글 · 숫자), 비밀번호는 6~12자에 대문자 · 소문자 필수입니다.
  • 가입 성공 시 클라이언트가 account_table에 계정 행을 직접 insert합니다.

FR-102 로그인

  • 이메일 + 비밀번호 로그인과 이메일 저장(쿠키 30일)을 제공합니다.
  • 소셜 로그인은 카카오 · 구글 · 깃허브 · 페이스북 4종을 제공합니다.

4.2 로비 · 방 관리

FR-201 방 목록 · 검색 · 생성 · 입장

  • 방 목록 실시간 갱신, 제목 검색(500ms 디바운스), 빠른입장을 제공합니다.
  • 방 생성 시 제목(최대 16자)과 인원수를 설정합니다. 지원 인원은 5~6명입니다.
  • 게임 중(is_playing)인 방은 입장을 차단합니다.
  • 방장은 입장 시각(join_time)이 가장 빠른 유저로 자동 지정 · 위임됩니다.

FR-202 준비 / 시작

  • 참가자가 전원 준비를 완료하면 방장 화면의 버튼이 [게임시작]으로 전환됩니다.
  • 시작 요청에 대한 서버측 검증이 없어, 방장이 아닌 유저의 시작 요청이나 중복 시작 요청도 처리됩니다 (§7 참조).

4.3 게임 진행

FR-301 사회자 자동 진행

  • 서버가 1초 간격 스테이트 머신으로 밤 → 낮 토론 → 투표 → 최후의 변론 → 찬반 → 밤 행동을 자동 진행합니다.
  • 단계별로 참가자의 캠 · 마이크를 서버가 일괄 제어합니다.
  • 세부 규칙은 §5, 라운드 타임라인 상세는 v2 문서 §5와 동일 구조입니다.

4.4 화상 · 음성

FR-401 LiveKit 기반 화상채팅

  • LiveKit Cloud(SFU)로 방 참가자의 영상 · 음성을 중계합니다.
  • 입장 전 캠 · 마이크 권한 확인과 미리보기 화면을 거쳐 방에 참여합니다.

4.5 랭킹 · 점수

FR-501 점수 반영 · 랭킹 조회

  • 게임 종료 시 승리 팀 +100점, 패배 팀 +20점을 부여합니다.
  • 점수 갱신을 클라이언트가 직접 수행합니다 (§7 참조).
  • 랭킹 페이지는 총점 내림차순 목록, 본인 순위 고정 표시, 10명 단위 페이지네이션을 제공합니다.

4.6 부가 기능

FR-601 튜토리얼 · 문의 · 안내

  • 게임 룰 튜토리얼 페이지(/mafiainfo), EmailJS 문의 폼, Typebot 챗봇 버블, 공지 팝업(하루 보지 않기)을 제공합니다.

5.게임 진행 규칙 (5~6인)

5.1 역할 분배

인원마피아경찰의사시민
5명1004
6명2103
참고: 의사 역할은 코드와 게임 룰 문서에 존재하지만, 5~6인 분배표에서 배정 인원이 0명이라 실제 게임에는 등장하지 않습니다. 경찰도 6인 게임에서만 등장합니다.

5.2 승리 조건

  • 생존 마피아가 0명이 되면 시민 팀 승리입니다.
  • 생존 마피아 수가 생존 시민 수 이상이 되면 마피아 팀 승리입니다.

6.데이터 명세

Supabase Postgres 테이블 3개로 구성됩니다. (컬럼 상세는 v2 문서 §6과 동일합니다.)

테이블역할
account_table계정 · 누적 점수 (마피아 / 노래맞추기 / 총점)
room_table게임 방 (제목 · 카테고리 · 방장 · 인원 · 게임 중 여부)
room_user_match_table방-유저 매칭 + 게임 상태 (역할 · 생존 · 준비 · 투표)
보안 구조: RLS(Row Level Security)가 적용되어 있지 않아 클라이언트가 anon key로 모든 테이블을 직접 읽고 쓸 수 있습니다. 마피아 role 컬럼도 클라이언트에서 조회 가능합니다.

7.알려진 한계 및 리마스터(v2) 방향

v1 한계v2 리마스터 방향
LiveKit Cloud(외부 SaaS) 의존 — 무료 쿼터 · 계정 종속 순수 WebRTC P2P mesh로 전환 (외부 미디어 서버 제거)
5~6인만 지원, 의사 역할 미배정 3~6인 지원 · 인원별 역할 분배 개편 (의사 · 경찰 정식 등장)
RLS 부재 — 클라이언트가 계정 생성 · 점수 갱신 · role 조회 가능 RLS 도입, 쓰기 전면 차단, role 컬럼 은닉, 서버(service_role) 단독 쓰기
게임 시작 검증 부재 — 아무나 · 중복 시작 가능 (게임 루프 다중 실행 사고) 방장 소켓 검증 + 게임 레지스트리로 중복 실행 차단
팀 계정 인프라(Supabase 등) 접속 불가 개인 계정 무료 인프라로 이전 (Vercel · Render · Supabase 신규 프로젝트)
GA 키 미설정 시 앱 전체 크래시 GA를 선택 환경변수로 전환 (키 없으면 추적만 스킵)
소셜 로그인 4종 유지 부담, 과도한 비밀번호 규칙 카카오 · 구글 2종으로 정리, 비밀번호 6~20자로 완화
