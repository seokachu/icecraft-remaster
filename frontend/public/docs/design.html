ICECRAFT — DESIGN SYSTEM

디자인 토큰 · 타이포그래피 · 컴포넌트 규격

실시간 화상 마피아 게임 IceCraft의 디자인 시스템입니다. 컬러와 타이포그래피는 Figma 디자인시스템에서 정의한 토큰을 그대로 따르고, 컴포넌트 규격은 서비스에 구현된 값을 기준으로 삼습니다. 아래 견본은 이미지가 아니라 실제 값으로 렌더링한 것입니다.

1.토큰 체계

값의 출처를 두 가지로 구분합니다. 디자인 토큰은 Figma 디자인시스템에 정의된 값, 구현 규격은 서비스 구현 과정에서 확정한 값입니다.

레이어수내용기준
컬러 토큰 6 Main · Sub · UIText/{Black White PlaceHolder Error} 디자인 토큰
텍스트 스타일 20 Pretendard 4웨이트 × 사이즈별, 행간 공식 내장 디자인 토큰
확장 팔레트 6 서피스 · 보더 · 보조 텍스트 — 구현에서 보강 구현 규격
컴포넌트 8 Header · Footer · Button · Game Card · Cam · ToolTip · CheckBox · Icon 구현 규격
CSS 변수로 관리합니다. Figma 토큰을 globals.css의 :root 변수 18개로 옮겨두고, 컴포넌트 스타일은 그 위에 CSS Modules로 쌓습니다. Sass나 Tailwind 없이 네이티브 CSS 변수만으로 테마를 관리하는 구조입니다.

3.타이포그래피

3.1 행간 공식 디자인 토큰

Line Height = 폰트 사이즈 + 8  /  35 이상은 + 15

타이포 스타일 20종 전체가 이 하나의 공식으로 생성됩니다 — 13 → 21, 16 → 24, 24 → 32, 그리고 큰 크기는 35 → 50, 40 → 55. 사이즈마다 행간을 따로 정하지 않아도 되므로 스케일을 확장해도 일관성이 깨지지 않습니다.

3.4 구현 운용 구현 규격

디자인 토큰의 스케일을 그대로 쓰되, 실제 화면에서 필요한 크기만 CSS 변수로 승격했습니다. 토큰을 전부 변수로 옮기면 쓰지 않는 값이 늘어나므로, 사용처가 확실한 6개만 남겼습니다.

CSS 변수값사용처
--font-size-content35px게임 타이머 · 404 본문 · 로딩 화면
--font-size-title20px섹션 · 카드 타이틀 — 최다 사용
--font-size-modal-title18px모달 소제목 · 입장 버튼 — 20과 16 사이가 필요해 구현에서 추가
--font-size-modal-content16px모달 본문
--font-size-small14px보조 텍스트 표준 — 라벨 · 배지 · 메시지
--font-size-base16px본문 기본 크기
--font-bold700제목 · 버튼 · 강조
웨이트는 2단계로 운용합니다. 본문 400, 제목 · 버튼 · 강조 700(--font-bold). 게임 서비스 특성상 화면당 정보 밀도가 높아, 웨이트를 잘게 나누는 대신 크기와 색으로 위계를 만드는 편이 읽기 쉽다고 판단했습니다.

IceCraft 게임 방법랭킹문의로그인

5.4 테마 운용

  • 라이트 기반 + 몰입 영역만 다크인 하이브리드입니다. 방 목록 · 랭킹 · 문의 · 폼은 라이트, 헤더 · 게임 방 · 캠 설정 · 게임 방법 인트로는 다크로 갑니다.
  • 헤더는 항상 #050b15로 고정해 라이트 화면에서도 브랜드 기준선을 유지하고, 푸터는 #eeeeee로 본문과 분리합니다.
  • 포인트 컬러는 화면당 한두 곳. Main은 주요 액션과 인원 배지에만 쓰고, 되돌릴 수 없는 액션에만 에러 레드를 예외로 허용합니다.
  • 게임 방의 낮/밤은 배경 이미지 교체로 표현합니다(대기 · 낮 · 밤 3종 AVIF). 색 오버레이가 아니라 이미지를 바꾸므로, 캠 위 정보는 어느 배경에서도 읽히도록 흰색 + 반투명 검정 레이어를 조합합니다.
  • 다크모드 대응은 하지 않습니다. prefers-color-scheme 대신 화면별로 테마를 고정합니다.

6.다음 단계

시스템을 더 단단하게 만들기 위해 계획하고 있는 작업입니다.

항목현재계획
보조 텍스트 토큰화 #747474가 확장 팔레트에만 있고 CSS 변수로는 없음 --text-sub로 :root 승격 + Figma에 UIText/Sub 추가해 양쪽 동기화
행간 토큰 도입 컴포넌트별로 px 지정 size + 8 공식을 CSS 변수로 옮겨 스케일 전체를 한 규칙으로 생성
웨이트 정리 400 · 700 2단계 운용 중, 600이 3곳에 잔존 잔여 3곳을 700으로 통합해 2단계 원칙 완전 적용
인풋 규격 통일 폼(radius 4px · #bfbfbf)과 검색 · 문의(8px · #d3d3d3)가 이원화 8px + 단일 보더 색으로 통일
아이콘 크기 정규화 용도별로 지정해 24 · 28 · 36 · 45px가 혼재 16 · 24 · 32 · 40 4단계로 묶고 Outlined · Round 중 한 스타일로 통일
토스트 커스터마이즈 react-toastify 기본 스타일 Main 기반 커스텀 테마 적용 — 브랜드 컬러가 닿지 않은 유일한 컴포넌트

7.부록 — 디자인 진행 과정

이 디자인 시스템은 세 단계를 거쳐 정리되었습니다.

단계산출물내용
01 와이어프레임 1728px 아트보드에 화면 48종의 배치와 기능 분기를 잡는 단계. 게임 방만 아침 · 밤 · 투표 · 찬반투표 · 사망 · 결과 등 17개 상태로 분기했습니다.
02 하이파이 시안 1920px 기준으로 전 화면을 시각화하고, 인풋 5개 상태 · 직업카드 · 모달 케이스를 별도 보드로 정리했습니다.
03 디자인시스템 컬러 6종과 타이포 20종을 스타일로 등록하고, 컴포넌트 보드 8종으로 재사용 단위를 확정했습니다. 이 문서의 토큰이 여기서 나왔습니다.

구현 단계에서는 3단계의 토큰을 :root 변수로 옮기고, 실제 사용 빈도에 맞춰 스케일을 추리는 방식으로 시스템을 좁혔습니다.
